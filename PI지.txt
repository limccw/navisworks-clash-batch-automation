## 1.0 목적 및 적용 범위

본 지침은 IM 담당 부서에서 수행하는 Ensemble+, 3D Admin, 공사IT, SM 프로젝트(이하 프로젝트라 함)의 구성, 수행방법, 절차 등을 기술하여 체계적이고 효율적으로 프로젝트를 추진할 수 있도록 하는데 그 목적이 있다.

## 2.0 참고 문서

Project IT Setup Guide

## 3.0 용어의 정의

### 3.1 IM

Information Management

### 3.2 LE

Lead Engineer

### 3.3 PM

Project Manager

### 3.4 전산 자원

컴퓨터 등 전산기 기나 동 기기를 이용하여 업무에 직간접적으로 기능하여 도움을 줄 수 있는 Hardware 및 Software 등을 말한다.

### 3.5 MDM

기준정보관리시스템(Master Data Management System), 전사의 프로젝트 정보를 통합하여 생성부터 준공 후 A/S까지 전체 Lifecycle을 관리하는 시스템을 말한다.

### 3.6 Hardware (H/W)

주전산기를 비롯하여 각종 서버, 컴퓨터 하드웨어 및 주변 장치를 말한다.

### 3.7 Software (S/W)

컴퓨터에 설치되어 업무에 이용되는 컴퓨터 운영 체계, 데이터베이스, 응용프로그램 등을 말한다.

### 3.8 Back-up

전산 프로그램이나 Data 파일이 파괴될 경우에 대비하여 별도의 자기테이프, 자기디스크 등의 기억 매체에 저장하여 보관하는 것을 말한다.

### 3.9 Restore

손상된 데이터의 복구 또는 지난 데이터를 참조하고자 하는 경우에 Back-up 받은 자기테이프, 자기디스크 등의 데이터를 하드디스크에 복사하는 것을 말한다.

## 4.0 책임 및 권한

### 4.1 Project IM LE (Lead Engineer)

1) 시스템이 안정된 환경에서 최적화되어 운영될 수 있도록 하며, 장애 발생 시 신속히 문제를 해결하여야 한다.
2) 시스템 운영 전반에 관하여 기획 설계하고 운영 및 관리 세부적인 사안에 대한 권한을 갖는다.
3) 수시로 전체적인 System Monitoring을 하여 문제를 예방한다.
4) 외부 협력사의 Ensemble+, 3D Admin, 공사용 도면 제작 지원 용역 업무에 문제가 없도록 협조한다.

## 5.0 절차

### 5.1 Project 인사 코드 부여

사업팀은 수주가 확정되면 사내공문으로 IM 담당 부서에 인사 코드 부여 요청을 하고 Project IM 담당자는 MDM에서 인사 담당 부서에 인사 코드 개설을 요청한다.

### 5.2 Project IT Setup 절차

#### 5.2.1 Project IT Setup Guide 배포

Project IM 담당자는 사업팀으로부터 Project LE 선정 요청 사내공문 접수 후 Project IT Setup Guide를 사업팀에 배포하고, IT 요건 및 적용범위를 파악하기 위한 IT Kick Off Meeting 및 Ensemble+ Setup을 위한 교육을 수행한다.

#### 5.2.2 Project 수행계획서

1) Project IM 담당자는 사업주 Requirement에 적합한 Project 수행계획서를 작성한다.
2) Project 성과품 목록에 Project 수행계획서가 포함되어 있는 경우 사업팀에 송부하여 사업주에게 제출한다.

#### 5.2.3 실행 예산 편성에 대한 협의

Project IM 담당자는 IT Cost견적시 산출한 금액 그대로 실행예산이 편성 되도록 Project 초기에 사업팀과 협의한다. (표준 예산 산출기준에 부합되도록 예산을 편성, 집행하기 위함)

#### 5.2.4 외주 업체와 하도급 계약실시

Project IM 담당자는 반영된 실행 예산을 확인하여 Project 수행을 위한 하도급 계약을 외주 업체와 체결한다.

#### 5.2.4.1 계약 기간

1) 사업팀 Baseline Schedule에 따른 업무 공정율 중심으로 산정한다.
2) Project 준공 시까지로 계약 기간을 산정한다.

#### 5.2.4.2 계약 방식

설계 외주관리 절차서에 준하여 외주 계약을 진행한다.

### 5.4 예산집행 및 기성확인 - (별첨1. 업무흐름도 1.4 참조)

#### 5.4.1 예산집행 및 기성확인 절차

1) 기성 확인 요청서 검토 (Ensemble+, 3D Admin, 공사용 도면제작 지원)
> Project IM 담당자는 외주업체로부터 기성 확인 요청서를 수령하여 산출 금액 및 Progress를 검토한다. 주요 검토사항은 아래와 같다.
① 기성 산출 내역
② 금액
③ M/H
④ Progress
⑤ 월간 인원 투입 현황
⑥ 업무별 인력 운영 현황
> Project IM 담당자는 자료 검토 시, Project별 기성 계획서와 조직 운영 계획서의 내역을 비교하여 실적을 확인해야 한다. 이 때 Proposal 예산과 사업팀 실행예산, 하도급 계약 전 후 예산과 기성금액 등의 적정성 여부를 통합적으로 분석해야 한다. 또한 당초 대비 금액 또는 인력이 변경 되었을 시 차이에 대한 원인을 파악하고, 파트장에게 변경 사항을 보고한다.
2) 기성 확인 통보서 작성
> Project IM 담당자는 해당 Project의 IT기성 확인 요청서의 승인 및 결재가 완료되면, 기성 확인 통보서를 작성하여 팀장의 승인을 받아 외주 업체에 발송한다.
3) 기성 청구서 수령 및 사업팀 전달
> Project IM 담당자는 해당 Project의 외주업체로부터 기성청구서를 수령하고 청구내역과 금액이 동일한지 확인하고 사업팀으로 기성 청구서를 전달하여 기성을 집행시킨다.
4) 실적 관리 및 운영 성과 평가
> Project IM 담당자는 전체 Project별 월간 기성 실적과 조직 운영 성과를 지속적으로 현황 유지 관리하여, 추후 Proposal / Project IT Cost 물량과 M/H 산출에 근거자료로서 활용한다.

① 각 업무담당자는 변경계약 내용을 사업팀과 협의한 후에 관련자료들을 작성하여 Project IM 담당자에게 제출한다.
② Project IM 담당자는 외주시스템을 이용하여 변경계약을 진행한다.

### 5.7 Project 종료보고

#### 5.7.1 Project IT 종료보고서 작성

Project IM 담당자는 프로젝트가 종료되면 Project IT종료보고서를 작성하여 각 부문 파트장 및 팀장 보고 후 사업팀 공무에게 전달한다.

1) Project 종료시점의 인식
① 해당 Project의 모든 IT관련 용역계약이 종료된 시점
② 해당 Project의 모든 DATA 이관이 완료된 시점
2) 종료보고서 작성시한
> Project 종료시점 이후 1개월 이내
3) 종료 보고 및 승인
> Project IM 담당자는 Project 종료보고서 작성 완료 후, 전자결재를 통하여 팀장 승인 절차를 거친다.
4) 종료보고서 작성내용
① Project 개요
> Project 코드, 이름, 현장위치, PM/SM 이름, 발주처(Owner), Licensor, 계약형태, 계약금액, 계약기간(당초/변경), IT Manager, CIMS Administrator, 적용된 IT 시스템 및 용역계약 여부, Project에 사용된 Engineering Tools 등의 내용을 작성한다.
② IT System 관련 업무 수행 Schedule
> 본사 IT 인프라 구축 및 Ensemble+ Setup부터 Data Handover 및 현장 서버 DATA 본사 이관까지의 Plan 대비 Actual Schedule 장표를 작성한다.
③ IT 예산 대비 집행 내역
> 외주용역(Ensemble+ Admin & Support, 공사용 도면제작 지원) 및 Engineering Tools 집행내역 장표를 작성한다.
④ Lessons Learned (성공, 실패 사례)
> Project 수행과정에서 발생한 주요 IT 문제점에 대한 원인과 조치사항을 기술하고 각각의 성공과 실패사례에서 얻은 교훈을 작성한다.
⑤ 현장 시스템 데이터 백업 및 자산처리
> 현장 시스템 장비 내역 및 해당 Project 종료 후 데이터 백업 및 자산 처리결과에 대한 내용을 작성한다.
5) 종료보고서 작성에 필요한 자료수집
> Project IM 담당자는 Project IT 실행내역을 각 담당자에게 요청하고 관련 자료를 확보한다.
① Engineering Tools (3D Model, 전기/계장/공정 설계, 사업관리, Engineering Data Handover 등)
② IT Systems (IT인프라, Ensemble+, ECS, DMCS+, PMCS+, FMCS+, CIMS 등)
> Project IM 담당자는 IM 담당 부서 및 IT 부서의 각 시스템 운영 담당자에게 Project에 적용된 IT System 수행 자료를 요청한다.

#### 5.7.2 해외현장 종료 시 서버 및 DATA 이관 절차

해외 프로젝트의 경우, 프로젝트 종료 후에 현장 또는 현지사업팀에서 별도로 운영한 서버 DATA 및 IT시스템의 DATA 통합 관리를 위해서 본사로 DATA 이관을 하여야 한다.

현장의 서버 DATA를 본사로 이관하기 위한 절차는 아래와 같다.

1) 현장 IT Supervisor는 현장 인터넷 연결 및 외장하드를 준비한다. (2TB 이상)
2) IT 부서 각 시스템 담당자는 각 서버에 접속하여 시스템 이미지 백업, DB 백업을 실시한다.
3) 현장 IT Supervisor는 백업파일, 문서파일을 외장하드로 복사한다.
4) 현장공무는 외장하드를 Project IM 담당자에게 송부한다.
5) IT 부서 각 시스템 담당자는 Data Restore 작업을 실시한다.
6) 현장 IT Supervisor는 현장 서버 디스크를 포맷한다.
7) 현장공무는 해외현장 IT인프라 처리내역 통보서를 작성, 정보보안 부서 및 IT 부서에 사내공문을 발송하여 공지한다. (현장 서버 타 현장 전출, 본사송부, 폐기에 대한 각각의 기준을 구분하여 표시 및 검토)

#### 5.7.3 프로젝트 EPC 지원 시스템 Type 별 DATA 이관계획

1) Ensemble+ (CCS, EDCS, VPCS, SITE CCS 등)
① 현장 IT Supervisor는 공사 종료 후 External HDD에 DB Backup 후 HDD를 본사 Project IM 담당자에게 송부한다.
② Ensemble+ Admin은 Backup data Restore 작업을 실시한다.
③ Ensemble+ Admin은 현장 앙상블 내 기존 동기화 된 CCS, EDCS, VPCS DB를 삭제한다.
④ Ensemble+ Admin은 Ensemble Portal Home > COMPLETED PROJECT에 종료된 현장 앙상블 도메인을 등록한다.
2) 조달 (PMCS+)
① IT 부서 PMCS+ 담당자는 시스템이 특정 project를 지원 하기 위해 독자적 Process 를 적용하였을 시, 내부 관리되는 Data Level이 상이하게 되므로 신규 서버로 이관작업을 실시한다.
② IT 부서 PMCS+ 담당자는 현장에서 사용했던 App. 소스 및 DB Data 모두 HDD 에 백업하여 보관한 뒤에 본사 서버에 이관작업을 진행한다.
3) 자재 (DMCS+, FMCS+)
① IT 부서 FMCS+ 담당자는 현장에서 운영 중인 모든 DMCS+ (FMCS+) Data가 매일 새벽 본사 DB로 정확하게 이관되고 있는지 모니터링 하여야 한다.
② IT 부서 FMCS+ 담당자는 해외에서 설계물량관리 시스템이 독립적으로 운영되는 경우 자재코드 체계가 상이하므로 신규서버를 별도로 요청해서 이관작업을 실시한다.
4) 공사 - 시공관리(CIMS), Turnover (iTOS)
① IT 부서 CIMS 담당자는 현장 별 Data Backup 일정에 따라 DB Export 실행 후에 dmp 파일을 현장에서 본사로 전송해서 파일로 관리하여야 한다.
② 현장 IT Supervisor는 공사 종료 후 External HDD에 DB Backup 및 현장서버 파일 복사 후 HDD를 본사 Project IM 담당자에게 송부한다.
③ IT 부서 CIMS 담당자는 현장 공사시스템 App. 소스 및 DB Data Scheme이 다른 경우 본사 CIMS로 DB파일 전송 및 이관 작업을 실행한다.

위 텍스트를 현재 열린 Word 문서에 그대로 Word 문서로 만들어줘. 규칙:
1. 맨 위 [작성 규칙] 블록과 이 [Claude 실행 프롬프트] 블록은 문서에 넣지 말 것.
2. 기존 문서 내용은 모두 지우고 새로 작성할 것. 섹션 단위로 나눠서 삽입할 것.
3. 글꼴: 본문 전체 맑은 고딕 10pt, 줄간격 1.15, 단락 뒤 6pt.
4. "#" → 제목(Title) 스타일, 가운데 정렬, 18pt 굵게.
   "[META]" → 제목 바로 아래 가운데 정렬 9pt 일반 문단 (태그 문자는 제거).
5. "[TOC]~[/TOC]" → "목차" 소제목(굵게) 아래에 각 줄을 일반 문단으로 넣고, x.0 줄은 굵게, x.y 줄은 왼쪽 들여쓰기 0.5cm. 목차 다음에 페이지 나누기.
6. "##" → Heading 1, "###" → Heading 2, "####" → Heading 3 스타일. 번호(1.0, 5.2 등)는 텍스트 그대로 유지하고 자동 번호 매기기는 쓰지 말 것. 모든 제목 스타일은 맑은 고딕, 검정색, Heading1 13pt / Heading2 11pt / Heading3 10pt 굵게.
7. "1) 2) …" 줄 → 왼쪽 들여쓰기 0.5cm, 내어쓰기 0.5cm 일반 문단.
   "① ② …" 줄 → 왼쪽 들여쓰기 1.0cm, 내어쓰기 0.5cm.
   ">" 로 시작하는 줄 → ">" 제거 후 왼쪽 들여쓰기 1.0cm 일반 문단.
   위 번호들은 텍스트 그대로 두고 Word 자동 목록으로 변환하지 말 것.
8. 빈 줄은 문단 구분용이므로 빈 문단을 만들지 말 것.
9. "[FOOTER]" 문구는 바닥글 왼쪽에 넣고, 같은 줄 오른쪽에 "페이지 {PAGE} / {NUMPAGES}" 필드를 넣을 것 (8pt).
10. 완료 후 제목 스타일 분포와 글꼴을 다시 읽어서 확인하고, 변경 내역을 짧게 보고할 것.
